# Windows 桌面连点器

一个使用 C#、WPF 和 MVVM 架构实现的 Windows 桌面连点器。

## 下载与运行

1. 打开仓库的 [Releases](https://github.com/SaintTemple/AutoClicker/releases) 页面。
2. 下载最新版本的 `AutoClicker-v*-win-x64.zip`。
3. 解压 ZIP 后双击 `AutoClicker.exe`，无需另外安装 .NET。

本程序目前没有代码签名证书。Windows SmartScreen 可能显示未知发布者提示；如果 Windows 11 的“智能应用控制”处于强制模式，系统可能直接阻止此程序，且目前没有针对单个应用的放行开关。请仅从本仓库的 Release 页面下载，并核对发布页提供的 SHA-256。要在智能应用控制开启时可靠运行，需要由可信证书签名或获得微软信誉服务认可。

## 功能

- 支持毫秒、秒、分钟三种间隔单位。
- 最小连点间隔为 10 毫秒。
- 支持鼠标左键、右键和中键。
- 支持录入并连续触发单个键盘按键。
- 默认使用 F6 作为全局开始/停止热键。
- 支持重新录入全局热键，并检测系统热键占用和按键冲突。
- 后台执行连点，不阻塞 WPF UI 线程。
- 关闭窗口时自动停止任务并注销全局热键。

## 环境要求

- Windows 10 或 Windows 11
- Visual Studio 2022 17.8 或更高版本
- Visual Studio 的“.NET 桌面开发”工作负载
- .NET 8 SDK

## 使用 Visual Studio 运行

1. 打开 `AutoClicker.sln`。
2. 将 `AutoClicker` 设置为启动项目。
3. 选择 `Debug` 和 `Any CPU`。
4. 按 `F5` 启动。

也可以在仓库根目录运行：

```powershell
dotnet build AutoClicker.sln -c Release
dotnet run --project AutoClicker/AutoClicker.csproj
```

## 操作说明

1. 输入连点间隔并选择单位。
2. 选择鼠标连点或键盘连按。
3. 键盘模式下，点击“录入按键”后按下一个按键；按 `Esc` 可取消。
4. 如需修改启停热键，点击“录入热键”，按下新按键，再点击“应用热键”。
5. 点击“开始”或按全局热键开始。
6. 点击“停止”或再次按全局热键立即停止。

运行期间所有配置区域都会锁定。需要修改间隔、目标键或热键时，请先停止。

## 手动测试清单

### 间隔校验

- 输入空值、`0`、负数和字母，确认无法启动。
- 输入 `9` 毫秒，确认显示“最小间隔为 10 毫秒”。
- 输入 `10` 毫秒，确认可以启动。
- 输入 `0.5` 秒，确认预览显示实际为 `500` 毫秒。
- 输入超大数值，确认显示超出范围。
- 测试粘贴非法文本，确认输入被拦截。

### 鼠标输入

- 分别测试鼠标左键、右键和中键。
- 移动鼠标后确认输入始终发生在当前指针位置。
- 运行时确认间隔和按键配置不可编辑。

### 键盘输入

- 在记事本中分别测试字母、数字、功能键、方向键和小键盘按键。
- 确认每次触发都包含按下和松开，不会出现按键保持按下。
- 尝试把连点键设为启停热键，确认程序拒绝冲突。

### 全局热键和生命周期

- 窗口失去焦点后按 F6，确认仍能开始和停止。
- 修改热键后确认旧热键失效、新热键生效。
- 尝试注册已被其他程序占用的热键，确认旧热键仍然有效。
- 快速重复按热键，确认不会在停止后因排队操作意外重新启动。
- 运行中关闭窗口，确认任务停止且进程正常退出。
- 重新启动程序，确认 F6 可以再次注册。

## Windows 权限说明

`SendInput` 受 Windows UIPI 权限模型限制。普通权限运行的连点器通常不能向管理员权限运行的目标程序注入输入。程序不会尝试绕过该限制；如确有需要，应让两个程序运行在相同的权限级别。

本项目不包含隐藏运行、反检测、反作弊规避或绕过软件安全机制的功能。
